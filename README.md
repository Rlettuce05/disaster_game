# DISASTER CASCADE — M0 ブラウザモック

架空都市を題材とするゲーム **DISASTER CASCADE** のM0操作モックです。M0の目的は完成イメージの共有であり、災害シミュレーションの検証ではありません。

## 起動

1. このフォルダの `index.html` を Chrome / Edge / Firefox などのブラウザで開く。
2. 「都市の分析を始める」から一連の操作を進める。

外部ライブラリ、バックエンド、通信は不要です。ローカルサーバーでも実行できます。

```sh
python -m http.server 8000
# http://localhost:8000/
```

## 実装内容

- 開始 → 都市分析 → 災害条件設定 → 演示再生 → 結果分析 → 再挑戦
- 架空都市「アルバ」の模式地図、施設のクリック詳細、主要依存線の表示
- 架空断層上の自由な震源指定（地図クリック・ドラッグ、位置スライダー）と、M6.5固定の西部・東部代表演示シナリオ
- RP超過とモデルの現実性制約を**別々に**表示するUI（どちらも仮仕様）
- 都市側の出動・非常用電源・復旧など、事前設定した行動の演示
- 再生/一時停止/1分単位のステップ送り・シーク/再生速度
- イベントの原因IDと派生先、因果関係の追跡、機能稼働率の表示
- 演示結果の比較、再挑戦

## 震源位置（架空断層上の自由選択）

- 災害条件設定画面の黄色い断層線をクリックするか、橙色の震源マーカーをドラッグします。マウスとタッチ操作に対応。
- 右側の位置スライダー（0〜100%、0.1%刻み）でも移動できます。キーボード操作はこのスライダーを利用してください。
- 指定位置は表示された折れ線上の最近点に吸着します。内部値は断層の西端を0%、東端を100%とした**線に沿った割合**です。地理座標や距離（km）ではありません。
- **M0は2区間の代表演示**です。西側半分（0%以上50%未満）は西部ケース、東側半分（50%以上100%以下）は東部ケースの固定結果を再生します。同一区間内で位置を変えても被害結果は変わりません。
- プレイヤーが指定した震源位置は観察画面の地図上に保持され、結果画面にも表示されます。あくまで位置指定UIの検証であり、被害の空間計算は未実装です。
- 上記断層の地形・線形・被害データは**完全に架空の模式図**で、実在断層の解析には使えません。

## 演示の時間刻み（Δt = 1分）

- 再生クロックは `00:00` から `06:00` まで **1分ずつ** 進みます（計361時点）。
- 前へ／次へボタン、時間バーもすべて1分刻みです。
- 既存の演示イベント（例：00:30、01:00）はそのまま維持します。毎分新しいイベントが起きるわけではありません。
- 都市機能の稼働率と施設の被害状態は、次の事前定義キーフレームが来るまで直前の値を保持します。中間時刻の数値は物理計算や補間結果ではありません。
- 通常の再生速度は **ゲーム内1分につき実時間0.12秒** です。`2×`、`4×` で再生間隔だけを変更し、ゲーム内Δtは変わりません。

## 明確な非対応範囲

- 震源の位置ごとの被害計算、地震の物理計算、被害の確率計算、都市側AIのリアルタイム判断、実データの取得
- スコア/RP/終局の実計算、地形や施設の実在位置の再現
- `M7.3` および `M8.2` の実行（それぞれRPエラーと現実性制約エラーの演示）
- 音響、セーブ・ロード、モバイル向け正式操作保証

**重要**：地図・施設・地震条件・数値・RP・災害経過・スコア・終局判定はすべて架空のダミー値です。科学的予測・現実の都市の脆弱性を示すものではありません。

## ファイル構成

- `index.html`：入口
- `css/style.css`：画面の見た目とレスポンシブ対応
- `js/data.js`：架空都市と演示2ケースの時系列データ（外部取得なし）
- `js/app.js`：画面切り替え、地図、イベント再生、操作処理
- `docs/screen-flow.md`：画面遷移と検収条件
- `docs/demo-script.md`：演示手順
- `docs/m1-questions.md`：次工程で検証すべき事項

## リポジトリでの構成

ルートの `index.html` を起点とする静的ブラウザモックです。旧式のシナリオ一覧用 `game.js` は使用しません。既存の `LICENSE` は維持します。追加した素材は自作の架空地図・UIであり、第三者の実在データは取得していません。
