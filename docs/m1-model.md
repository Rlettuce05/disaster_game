# M1プロトタイプ: 計算モデルと検証

## 対象と目的
架空都市アルバで、地震の規模・位置、インフラ相互依存、消防判断に応じて災害連鎖が変わることを確かめる。
M0の固定演示は変更しない。M1は m1.html から起動し、js/m1-sim.js が361時点（0〜360分）の状態を生成する。

## モデル（科学的な被害予測ではない）
- 震源は架空断層ポリライン上の相対位置（0〜1）で表す。
- M値と模式距離から、便宜上の揺れ係数 h=clip((0.92+0.28(M-6))exp(-d/255),0,1) を算出。
  h は気象庁震度・地表最大加速度・実測値ではない。
- 水道・電力・道路は施設ごとのしきい値で損傷し、供給能力を毎分更新する。
- 火災は住宅地区の揺れ条件で発生し、水道能力と消防隊到着・消火によって規模が変化する。
- 道路閉塞は震災の直接被害か延焼により発生し、消防の到着時間と医療アクセスへ影響する。
- 病院の非常用電源は観測後に稼働する簡易ルール。消防AIは通報を受けて初めて出動を決める。
- 電力・水道は簡略化した復旧を行う。
- これらの閾値・式・復旧速度はすべてM1用の暫定的なゲームモデルである。

## 状態と更新
1. 時刻0に地震入力を確定する。
2. 時刻1以降、直接損傷、水道・電力の供給、火災、都市AI、道路、医療を順に毎分更新する。
3. 毎時刻に電力・水道・交通・消防・医療の稼働率（0〜100%）と、影響を受けた施設を記録する。
4. 各イベントは id、time、kind、key、place、causes、context、basis を持つ。
   causes は実際の発生原因のID、context は対応行動などの補助情報であり、混同しない。

## 比較指標
- 平均機能損失: 全361時刻×5系統の (1-稼働率) の平均。
- 最終機能損失: 時刻360の5系統の平均。
- 連鎖深さ: hazard / damage / cascade をたどる最長因果辺数。
- 波及範囲: 途中で稼働率が100%未満となった系統数。

正式な勝敗判定・最終スコア・RPルールの合意はM2に回す。
M1画面の「機能低下が残存／概ね回復」は暫定的な区分である。

## 検証
- P-01: 同規模・位置変更。計算された施設損傷と時系列を比較する。
- P-02: 同じ火災で道路を通行不能にし、消防到着の遅れを比較する。
- P-03: 消防AIの有無で結果を比較する。
- P-04: 同一条件・seed=42で再実行し完全一致を確認する。
- P-05: 因果イベントIDを遡り、発災までつながることを確認する。

実行:
  node --test tests/test_m1_sim.cjs
  node scripts/run-m1-experiments.cjs
  node scripts/run-m1-experiments.cjs --json

## 限界とM2への持ち越し
- 架空都市であり、現実の震度、被害率、インフラ機能の推定には使えない。
- 道路網は最短経路探索ではなく、幹線道路と迂回路の簡易モデル。
- 医療サービスと非常用電源は集約変数であり、患者動態や燃料消費はない。
- 発災後のプレイヤー介入、複数都市、高度なAI、正式なRP・勝敗は未実装。
- 実際のプレイテストによる「戦略として面白いか」の検証は未完了。
