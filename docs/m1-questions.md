# M1で解決すべき不確実性

1. **都市機能モデル**：電力、水道、道路、消防、医療をどの状態変数と関係式で表すか。依存関係を有向グラフにするだけでゲーム性を検証できるか。
2. **地震入力**：位置・規模から各施設の一次被害へ至る最小計算則をどう置くか。地震強度・マグニチュード・施設被害を混同しない設計が必要。
3. **連鎖の成立**：西部と東部で結果が違うことを、事前シナリオでなく実計算から再現できるか。条件の微調整に反応するか。
4. **都市側の行動**：観測情報と非公開情報を分離したうえで、少なくとも消防出動等の1つの意思決定を実装できるか。
5. **因果ログ**：二次災害と都市側行動が複数の原因を持つとき、イベントID・原因IDを自動記録できるか。特に「被害を発生させた原因（causes）」「緩和・対応行動（context）」「対策によって実際に生じた改善効果」を分離し、何を根拠として因果辺を作るか。緩和を意図した行動を説明なしに被害拡大の原因にしない。
6. **再現性**：同一初期条件と乱数シードでログ・結果が一致するか。
7. **ゲーム性**：同規模でも入力位置や都市側の対処によって異なる連鎖が生じ、その違いをプレイヤーが理解できるか。
8. **設計の未決事項**：災害発生後にプレイヤーが追加の一次災害を発生させられるか、終了条件やRP正式ルールをどう設計するか。
9. **スコア・終局判定**：因果辺数（有害な事象のみを追う深さ）、一度でも影響を受けた系統数、最終時刻の機能損失、RP効率などの指標をどのように正式なゲームルールへ統合するか。M0の82点/27点や崩壊・収束区分は固定演示であり、表示用の数式が確定したものではない。

M1では画面デザインの完成ではなく、因果モデルが動くことと比較実験を最優先する。


### 震源位置の連続入力から物理演算への接続

M0では架空断層線上の相対位置を自由指定するUIのみを用意したが、結果は西部・東部の固定演示に量子化される。M1では、震源位置の連続的な変化が被害分布・連鎖に反映される最小モデルと、位置を変更した比較実験を設計する必要がある。断層の定義（幾何・深さ）と地震の強さの表現は物理モデルの設計事項であり、M0の模式線をそのまま地震計算に用いない。
